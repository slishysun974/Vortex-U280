# 同一张 U280 上，PTX 做 Iris 分类要多花多少时间？

一次处理 65,533 条样本，原生 Vortex C++ 用了 **98.03 毫秒**，当前 PTX 内核用了 **101.35 毫秒**。两种实现算出的分类和距离逐条相同。PTX 用时多 **3.39%**，完成的设备指令数却是 C++ 的 **3.14 倍**。

## 换个批量，结果怎样？

从 1,024 条到 65,533 条，四档测试中 PTX 的指令数都约为原生 C++ 的 3.14 倍，设备用时多出 0.24% 到 3.39%。小批量的相对差距更大。一次只处理 45 条时，PTX 多用约 36%，折算下来约为 **28 微秒**。

| 每批样本数 | 原生 C++ 用时（毫秒） | PTX 用时（毫秒） | PTX 多用时间 |
|---:|---:|---:|---:|
| 45 | 0.077 | 0.104 | 35.97% |
| 150 | 0.230 | 0.256 | 11.21% |
| 1,024 | 1.522 | 1.557 | 2.29% |
| 4,096 | 6.162 | 6.177 | 0.24% |
| 16,381 | 24.755 | 25.145 | 1.57% |
| 65,533 | 98.032 | 101.353 | 3.39% |

两种实现交替在同一张 200 MHz 的 U280 上运行，使用相同的输入和模型。每档各测 30 次，表中用时取设备执行周期的中位数，再换算成毫秒。最大档使用合成样本测吞吐，共有 30 对正式测量，每一对都是原生 C++ 更快。

## 指令数能预测用时吗？

就这两个内核而言，直接按指令数估算耗时，会明显高估 PTX 的开销。最大档按线程组（warp）统计，C++ 完成约 **151 万条**指令，PTX 完成约 **474 万条**。设备忙碌的时间分别为 **1,961 万**和 **2,027 万**个时钟周期。要解释这段时间里有多少用于计算、多少用于等待，还需要更细的测量。[六档设备周期和指令数](../results/iris-pair-review-20261123-v1/receipt.json) · [逐次测量](../results/iris-board-pair-20261123-v2/returned/iris-board-pair-20261123-v2/u280-xrt/samples.jsonl)
