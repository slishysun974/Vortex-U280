# V08 单智能体与双智能体配对实验

2026-11-22 冻结，版本 `V08-ai-paired-v1`。E 管理发题和独立验收。研究问题是在相同总预算下，增加一个负责审查的智能体，会怎样影响离线编程任务的正确完成率、用时和成本。实验单位是一个任务变体的一次提交。六对共 12 个席位，每组 6 次。题目使用合成输入，结论限于这六类微任务。[研究计划](../../docs/RESEARCH_PLAN.md#6-ai-智能体的使用与对照实验)

## 题目与预算

| 对号 | 要交付的行为 | A / B 对应变化 |
|---|---|---|
| T1 | 给出首个前端诊断，保留错误优先级和寄存器定义顺序 | 加法 / 减法片段 |
| T2 | 连续同谓词访存组成条件块，保留顺序及谓词重定义边界 | 两组等价访存与定义指令 |
| T3 | 按字段自然对齐打包小端参数，拒绝首个越界值 | 十进制 / 十六进制输入 |
| T4 | 回放单槽超时、排空及锁存故障，逐事件给出响应 | 提交槽 / 事件槽 |
| T5 | 为合成的 RTL ready/valid 采样判定握手与首个稳定性违例 | 高有效 / 低有效接口 |
| T6 | 对齐乱序快照，定位首个异常阶段、记录和偏差原因 | 打包与采集 / 生成与读回 |

每席位 **45 分钟、60,000 个模型 token、零额外工具费用**。12 次合计上限为 9 席位小时、720,000 token。使用相同的 `gpt-6.2-sol`、medium、priority 和 CPython 3.13.13。单智能体自己实现、自测和复核。双智能体由一个实现者和一个审查者协作，两者共用同一时钟与 token 额度。技术资料、工具和可交付文件相同。[冻结参数与组别指令（本地归档）](../../docs/LOCAL_ARCHIVE_INDEX.md#archive-48bf628d0e7b)

- 计时从首次向任一模型投递该卡开始，到操作者封存最终 `solution.py` 为止。模型等待、工具调用、同组沟通均计入。两智能体并行 5 分钟按 5 分钟墙钟计，各自的 token 全部累加。独立验收所用时间另记。
- 使用每次请求的实际 input + output 总数，包含系统提示、历史重传、工具内容和审查轮次。供应方已计入输入的缓存 token、已计入输出的推理 token 不再加一次。有实际账单时另记金额、币种和计费口径。正式开跑前用无关文本确认计量、模型标识、剩余额度与截止控制可用。每批并行请求共同预留剩余 token，截止或用尽即停止；越限的提交不能接收。
- 人类操作者发题、转发同组意见、记录过程和封存文件。两组均允许本地编辑器、终端、标准库和自拟测试。人工解题或改码预算为 0。实施者只能看到导出的单卡工作目录，环境不挂载完整项目、其他任务、私测或旧会话；执行模型调用以外的工具使用本地离线资源。

## 分组、顺序与人员

在任何受试提交之前，以固定种子 `V08-20261122-v1` 对六个题对做分层分配。`study.py verify` 输出权威顺序。对每个标签按 `SHA256(seed/label/T编号)` 从小到大排序，前三项分别决定 A 分给单智能体、P 操作单智能体、单智能体先做；第四个标签决定题对顺序。每组恰好取得三个 A 和三个 B，各有三次先做。每对由两位不同操作者完成，P/Q 各做三次单智能体和三次双智能体。[分配实现（本地归档）](../../docs/LOCAL_ARCHIVE_INDEX.md#archive-3ef94297292c)

E 在开题前登记两位未接触卡面或私测的操作者及其相关经验，固定 P/Q 与姓名的对应。每个席位创建新工作目录、新模型上下文，按登记顺序发放一个变体。关掉跨会话记忆和共享解题记录。两位操作者在配对任务都封存前不交换题目或解法。E 保管验收材料；正式接收和重放者均独立于该提交作者。设计和校验冻结包时使用的智能体不计入受试组。

## 单卡发放与独立验收

以下示例从项目根目录在 PowerShell 执行。每个正式席位使用新 `run_id` 和新的结果目录，保留原始失败。示例中的 T1A 由 E 按冻结顺序替换。正式发题前，核对 `manifest.json` 的 SHA-256 与状态页所链冻结回执记录相同，然后校验清单内各文件。

```powershell
$study = 'experiments/ai-paired-v1/study.py'
Get-FileHash 'experiments/ai-paired-v1/manifest.json' -Algorithm SHA256
python -B $study verify
python -B $study issue T1A .\participant-T1A
```

E 仅把 `participant-T1A` 的四个文件放入该席位的工作环境。`card.json` 含组别说明、题目契约和一个有答案的公开样例。参与者可在其目录执行 `python -I -B run_card.py public.json public-observed.json`，自行比较 `cases[0].actual` 和卡面 `example_output`。允许修改 `solution.py` 与另写临时自测，结题只收 `solution.py`。到时封存源码、SHA-256、时间戳、过程记录与公开自测结果；E 的隐藏判分在封存后进行。

E 在验收端执行下列命令导出纯输入。另在两个全新离线工作目录分别放入同一份封存源码、冻结的 `run_card.py` 和导出的 `private-inputs.json`。带答案的 `private/cases.json` 只保存在 E 的评分端。两次完整重放各限 30 秒，保留命令、原始 stdout、stderr、退出码和输出 JSON，收回两份输出为 `replay-1.json`、`replay-2.json`。

```powershell
python -B $study inputs T1A private-inputs.json
# 在两个独立工作目录分别执行
python -I -B run_card.py private-inputs.json observed.json
# E 在评分端用封存原件及收回的两份输出判分
python -B $study grade T1A solution.py replay-1.json replay-2.json
```

**接收条件**为预算和工具规则满足、按时封存、两次独立重放均退出 0，且每项隐藏输出精确匹配。判分器同时检查卡号、源码哈希、用例顺序与条数。JSON 对象忽略键序，数组保持顺序，整数、布尔、字符串类型参与比较。异常、超时、缺失记录和任何一例错误均使功能验收失败。每席位仅一次封存，隐藏结果在配对两席均完成后披露；公开自测次数和修订轮数单列。预算和独立环境由 E 依据日志核签，判分器的退出 0 只覆盖功能重放。

## 原始记录与统计

E 为每席位留存分配序号、题号、组别、操作者及经验、接收人、模型与可得的部署版本、工具版本、冻结摘要、发放与封存时间、提交哈希、全部提示/交接/改动和命令。逐调用记录上下文标识、输入/输出 token，与账单可得性。人类主动分钟和等待分钟分开，记录自测修订次数、失败原因、接口缺陷和两次验收结果。可得费用按实际金额汇总。所有人员记录使用研究编号，不收集凭据。

主指标是预算内通过独立接收的席位数 / 6，分别报两组；逐对列出双过、仅单组过、仅双组过、双未过。预先保留全部 12 个分配席位。已开题但功能失败、超时、越限或未提交记 FAIL。外部条件无法提供记 BLOCKED，尚未开始记 NOT_RUN，不能用同题重试替换。若有未开或受阻席位，另报已开数、覆盖率及原因，保留原分母。基础设施复查只可同一封存哈希，记录所有尝试。

次指标按题对列出墙钟、累计 token、人工主动时间、费用（若可得）和首次提交质量；同时报告原值、配对差与中位数。缺失计量标记缺失并说明原因，无从确认预算时不签收。每对只有一组对照，报告样本量、相近变体和操作者经验带来的限制。若冻结后发现题面或答案有误，保留 v1 和既有记录，登记受影响席位，修订另立版本。
